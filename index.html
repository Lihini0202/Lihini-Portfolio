Holo

A logistic regression model that reads three signals in a chat (relative message length, return questions, reply rhythm) and sorts it into a ghosting-risk band. I chose it over gradient boosting because boosting ranked a clearly cold chat below a mildly cold one, and CI now checks that ordering on all 20 input combinations.

0.9154held-out ROC-AUC
91.9%ghosted in top band

scikit-learn · FastAPI · Celery · Supabase · Flutter

LLM evaluation

AgentBench

A controlled test of five agent setups, from one LLM call to a four-role pipeline, on real SWE-bench bugs with the same model. The extra agents fixed no more bugs and cost up to 4.5× the tokens. Getting a fair result meant first finding twelve harness failures that looked like model failures.

4.5×tokens, no extra fixes

About me

A designer who can ship the code too

I started on the engineering side, building features at WSO2. Working on privacy and consent screens showed me how much a clear interface matters when people make decisions about their own data.

Now I design in Figma, build in HTML, CSS, JavaScript and Flutter, and check everything with Lighthouse.

An engineer who tests the model before trusting it

I like ML that has to work outside a notebook. For Holo I picked a simple model over a stronger-looking one because it kept risk in the right order, and I added a CI check so it stays that way.

When I compared multi-agent and single-agent LLM setups, half the work was finding harness bugs that looked like model failures. I ship with tests, Docker and CI so the numbers can be trusted.

Process

How I work on UI/UX

UI/UX

  1. ListenLearn who the users are and what they need to get done.
  2. DesignSketch, then build clickable screens in Figma.
  3. BuildTurn the design into fast, accessible code.
  4. ImproveTest it with real people, then fix what's not working.

AI/ML

  1. DefinePick a real problem and decide how to measure success.
  2. BaselineStart simple, so I know what "better" means.
  3. ExperimentTry models and setups, tracking accuracy and cost.
  4. ShipDeploy what works, with tests and monitoring.

Research

  1. QuestionStart from something people actually struggle with.
  2. ReadFind what's already known and where the gap is.
  3. StudyCollect data, build a system, and test it fairly.
  4. PublishWrite it up clearly and share it for review.
